# EAC Terminal-Authentication test material

This directory contains a self-consistent CVCA + terminal certificate kit
generated by `generate_eac_material.py` (run it to regenerate):

| File | Purpose |
|------|---------|
| `cvca_ec_key.pem` | CVCA **private** key (NIST P-256) — issuing env only |
| `cvca_selfsigned.cvcert` | Self-signed CVCA certificate (CAR `UTSTCVCA00001`) — provision into the applet as the TA trust point |
| `terminal_ec_key.pem` | Terminal (Inspection System) **private** key (NIST P-256) |
| `terminal.cvc` | Terminal certificate (CHR `TERM0001`, rights `0x03` = DG3+DG4), signed by the CVCA |

All EC keys are NIST P-256 (secp256r1); the certificates carry explicit domain
parameters so the applet can reconstruct the keys.

## Using the kit in the GUI

1. After a successful **Read** and **Chip Authentication (CA)**, run
   **Terminal Authentication (TA)**.
2. Select `test_data/terminal.cvc` as the terminal CVC.
3. Select `test_data/terminal_ec_key.pem` as the terminal EC private key.

The reader derives the CVCA CAR and terminal CHR from the CVC, uses the IC's
PACE ephemeral X as `ID_IC`, and signs `ID_IC || r_IC || Comp(PKDH,IFD)` with
ECDSA-SHA-256.

## Provisioning the applet

The applet must trust the CVCA in `cvca_selfsigned.cvcert`. Because the
installed card's CVCA private key is not available, (re)personalize the applet
with this certificate so the terminal certificate verifies:

- Replace the personalization CVCA cert
  (e.g. `emrtd/test_data/UTSTCVCA00001.selfsigned.cvcert`) with
  `test_data/cvca_selfsigned.cvcert`, or provision the CVCA public point
  (`cvca_selfsigned.cvcert` tag `0x86`) + CAR (`0x42`) directly, then re-run
  personalization.
