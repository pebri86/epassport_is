# EAC Terminal-Authentication test material

This directory contains a self-consistent CVCA -> DV -> IS certificate chain
generated by `generate_eac_material.py` (run it to regenerate). All keys are
on **brainpoolP256r1**, matching the applet's Terminal-Authentication domain:

| File | Purpose |
|------|---------|
| `cvca_ec_key.pem` | CVCA **private** key (brainpoolP256r1) — issuing env only |
| `cvca_selfsigned.cvcert` | Self-signed CVCA certificate (CAR `UTSTCVCA00001`) — provision into the applet as the TA trust point |
| `dv_ec_key.pem` | DV **private** key (brainpoolP256r1) — issuing env only |
| `dv.cvc` | DV certificate (CHR `UTSDV00001`, role DV), signed by the CVCA |
| `terminal_ec_key.pem` | Terminal (Inspection System) **private** key (brainpoolP256r1) |
| `terminal.cvc` | Terminal / IS certificate (CHR `TERM0001`, rights `0x03` = DG3+DG4), signed by the DV |
| `cvca2_ec_key.pem` | CVCA2 **private** key (brainpoolP256r1) — issuing env only (`--link`) |
| `cvca_link.cvc` | CVCA **link (rotation)** certificate: CVCA1 certifies CVCA2 (CHR `UTSTCVCA00002`, role CVCA) (`--link`) |
| `dv2_ec_key.pem` / `dv2.cvc` | DV2 key + certificate signed by CVCA2 (CHR `UTSDV00002`) (`--link`) |
| `terminal2_ec_key.pem` / `terminal2.cvc` | Terminal2 key + IS certificate signed by DV2 (CHR `TERM0002`) (`--link`) |

The certificates are slim (~210 bytes each): the public key carries only the EC
point (tag 0x86). The applet verifies Terminal Authentication on its own
configured brainpoolP256r1 domain (TrustStore / DomainParameterManager), so the
certificates do not embed the explicit domain parameters. Keeping them small
means the SM-protected PSO:VERIFY fits a short (non-extended) APDU. The
generator uses the `cryptography` package (pycryptodome has no brainpool
support); the reader's Terminal-Authentication signing is dependency-free,
running on the pure-Python curve arithmetic in `epassport_reader/pace.py`
(matching how Chip Authentication already handles brainpoolP256r1).

## Using the kit in the GUI

1. After a successful **Read** and **Chip Authentication (CA)**, run
   **Terminal Authentication (TA)**.
2. Select `test_data/dv.cvc` **then** `test_data/terminal.cvc` as the terminal
   CVC chain (chain order: DV first, then the IS certificate).
3. Select `test_data/terminal_ec_key.pem` as the terminal EC private key.

The reader derives the CVCA CAR (from the DV certificate's issuer) and the
terminal CHR (from the IS certificate), uses the IC's PACE ephemeral X as
`ID_IC`, and signs `ID_IC || r_IC || Comp(PKDH,IFD)` with ECDSA-SHA-256 on
brainpoolP256r1.

## Testing the CVCA link (rotation) certificate

Regenerate the kit with `--link`, then during TA select the rotation chain:

1. Select `test_data/cvca_link.cvc`, then `test_data/dv2.cvc`, then
   `test_data/terminal2.cvc`.
2. Select `test_data/terminal2_ec_key.pem` as the terminal EC private key.

The link certificate (role CVCA, issuer `UTSTCVCA00001`) is verified against
the provisioned CVCA1 trust point and rotates the trust anchor to CVCA2
(`UTSTCVCA00002`); the DV2 and terminal2 certificates then chain under CVCA2.
This must be sent against a card personalized with `cvca_selfsigned.cvcert`
(the CVCA1 trust point).

## Provisioning the applet

The applet must trust the CVCA in `cvca_selfsigned.cvcert`. Because the
installed card's CVCA private key is not available, (re)personalize the applet
with this certificate so the chain verifies:

- Replace the personalization CVCA cert
  (e.g. `emrtd/test_data/cvca_selfsigned.cvcert`) with
  `test_data/cvca_selfsigned.cvcert`, or provision the CVCA public point
  (`cvca_selfsigned.cvcert` tag `0x86`) + CAR (`0x42`) directly, then re-run
  personalization.
